# /recipe — Recipe Recommender

식재료 인벤토리(JSON)를 읽어 한식 레시피를 추천하고, 선택된 레시피를 마크다운 파일로 저장합니다.

## 기본 제약 (사용자 프로필)

사용자는 주로 **아내와 둘이서** 먹기 위해 요리하며, **요리 경험이 많지 않은 초급자**입니다. 다음 제약을 **항상 적용**하고, 사용자가 명시적으로 다른 값을 요청할 때만 재정의:

- **인분**: 2인분 기준
- **조리 시간**: 20분 이내
- **난이도**: 초급자 친화 (★★☆ 이하) — 단, **만족도가 높은** 검증된 가정식 위주
- 복잡한 칼질·장시간 끓이기·전문 도구 필요한 레시피는 추천 후보에서 제외
- 추천 시 각 후보가 위 제약을 만족하는지 시간/난이도를 명시

## 데이터 위치

- **인벤토리 (입력)**: `week-4/레시피앱/ingredients/*.json`
- **레시피 저장 (출력)**: `/Users/henrykim/Downloads/HARBOR/test-01/week-4/레시피앱/recipe/`

(현재 작업 디렉토리 기준 상대 경로. 사용자가 다른 경로를 지정하면 그 경로 사용.)

각 인벤토리 파일 스키마:
```json
{
  "id": "egg",
  "name": "계란",
  "nameEn": "Egg",
  "category": "유제품/난류",
  "quantity": 10,
  "unit": "개",
  "expiryDate": "2026-05-10",
  "storage": "냉장",
  "emoji": "🥚"
}
```

## 워크플로우

1. **인벤토리 로드** — `python3 scripts/inventory.py [경로]` 실행
   - 경로 생략 시 기본 경로 자동 탐색
   - 출력: 카테고리별로 정렬된 재료 + 유통기한 임박 경고
2. **추천 선정** — 아래 "추천 우선순위" 적용해 3~5개 레시피 후보 제시
3. **레시피 생성** — 사용자가 선택하면 "레시피 출력 포맷"에 맞춰 상세 레시피 생성
4. **마크다운 저장** — 생성한 레시피를 다음 규칙으로 파일 저장:
   - 디렉토리: `/Users/henrykim/Downloads/HARBOR/test-01/week-4/레시피앱/recipe/`
   - 파일명: `YYYY-MM-DD-<레시피-슬러그>.md`
     - 슬러그는 한글/영문 그대로 두되 공백은 `-`로, 특수문자는 제거 (예: `김치-찌개`, `마늘-간장-삼겹살`)
   - 동일 파일이 이미 있으면 덮어쓰지 말고 끝에 `-2`, `-3` 붙여 새 파일 생성
   - 저장 후 사용자에게 "✅ 저장됨: <전체경로>" 한 줄로 알림
   - 저장은 반드시 `Write` 도구 사용 (Bash heredoc 금지)

### `/recipe` 트리거 시 기본 동작

- `/recipe` (인자 없음) → 인벤토리 로드 → 후보 3~5개 제시 → "어떤 거 만들래?" 묻기 → 선택받으면 상세 레시피 생성 + 자동 저장
- `/recipe <레시피명>` → 인벤토리 확인 → 해당 레시피 곧바로 생성 + 자동 저장
- `/recipe 임박` 또는 `/recipe 유통기한` → 임박 재료(D-7 이내)만 활용한 추천 우선

## 추천 우선순위

먼저 "기본 제약" (2인분 / 20분 이내 / 초급) 을 만족하는 레시피로 후보를 좁힌 뒤, 다음 순서로 가중치 적용:

1. **만족도** — 초급자가 만들어도 실패 확률 낮고 맛이 안정적인 검증된 가정식 우선
2. **유통기한 임박** (오늘로부터 7일 이내) 재료를 우선 — 버려지지 않게
3. **재료 활용도** — 인벤토리의 더 많은 재료를 활용하는 레시피 우선
4. **카테고리 균형** — 단백질(육류/난류/콩류) + 채소 + 양념이 섞인 레시피 선호
5. **한식 우선** — 김치/간장/마늘 같은 한식 재료가 있으면 한식 위주로
6. **수량 충분성** — 2인분 기준 필요량이 보유량을 초과하지 않을 것

## 레시피 후보 제시 포맷

추천을 보여줄 때 (화면 출력만, 저장 안 함):

```
## 🍳 추천 레시피 (현재 인벤토리 기준)

**⚠️ 유통기한 임박**: <재료명> (D-N), <재료명> (D-N)

1. **<레시피명>** <emoji>
   - 사용 재료: <재료1>, <재료2>, ...
   - 소요 시간: ~N분 / 난이도: ★☆☆
   - 추천 이유: <임박 재료 소진 / 인벤토리 활용도 등>

2. ...

어떤 거 만들까요? (번호 또는 이름)
```

## 레시피 출력 포맷 (저장 파일 형식)

상세 레시피 — 화면 출력과 저장 마크다운 모두 동일한 본문 사용. 저장 파일은 맨 위에 YAML 프론트매터 추가:

```markdown
---
title: <레시피명>
date: <YYYY-MM-DD>
servings: <N>
duration_min: <N>
difficulty: <1~5 별 개수>
used_ingredients: [<id1>, <id2>, ...]
---

# <레시피명> <emoji>

**소요 시간**: N분 | **난이도**: ★★☆ | **인분**: N인분

## 재료 (인벤토리에서 사용)
- <재료> <필요량> (보유: <보유량>)
- ...

## 추가 필요 재료 (인벤토리에 없음)
- <재료> <양> — 일반적으로 마트/편의점에서 구매 가능

## 조리 순서
1. ...
2. ...

## 팁
- <한식이면 매운맛/간 조절, 보관법 등>

## 인벤토리 차감 결과 (시뮬레이션)
- <재료>: <기존> → <차감 후>
```

## 알려진 레시피 풀 (인벤토리 기반 매칭에 사용)

매칭은 "필요 재료가 인벤토리에 모두 또는 주요 부분이 있는가"로 판단. ⏱ 컬럼은 2인분 기준 예상 조리 시간 — **20분 초과는 기본 후보에서 제외**.

| 레시피 | 핵심 재료 | ⏱ 시간 | 난이도 | 만족도 |
|---|---|---|---|---|
| 김치볶음밥 | 김치, 계란, 대파 (+밥) | 12분 | ★☆☆ | 매우 높음 |
| 두부김치 | 김치, 삼겹살, 두부, 대파 | 15분 | ★☆☆ | 매우 높음 |
| 계란말이 | 계란, 대파 (+당근) | 10분 | ★★☆ | 높음 |
| 치즈 계란말이 | 계란, 체다 슬라이스 치즈, 대파 | 10분 | ★★☆ | 매우 높음 |
| 마늘 간장 삼겹살 | 삼겹살, 마늘, 간장, 대파 | 15분 | ★☆☆ | 매우 높음 |
| 두부 조림 | 두부, 간장, 마늘, 대파 | 15분 | ★☆☆ | 높음 |
| 계란찜 | 계란, 우유 또는 물, 대파 | 12분 | ★☆☆ | 높음 |
| 양파 계란볶음 | 양파, 계란, 간장 | 8분 | ★☆☆ | 높음 |
| 삼겹살 김치 볶음 | 삼겹살, 김치, 대파, 마늘 | 15분 | ★☆☆ | 매우 높음 |
| 그릴드 치즈 (변형) | 체다 슬라이스 치즈, 우유 (+식빵) | 8분 | ★☆☆ | 높음 |

**제외(20분 초과 또는 난이도 ↑)**: 김치찌개(끓이는 시간), 우유 계란 푸딩(중탕 오래 걸림). 사용자가 명시적으로 요청하면 그때 안내.

위 풀에 없어도 인벤토리에 따라 **20분 이내 / 초급자 / 2인분** 조건을 만족하는 새로운 조합을 자유롭게 제안 가능. 단, 한국 가정에서 일반적으로 만들 수 있는 현실적 레시피여야 함.

## 사용 예시

사용자: `/recipe`
→ 인벤토리 로드 → 추천 3~5개 제시 → 선택 받기 → 상세 레시피 생성 → 자동 저장

사용자: `/recipe 김치찌개`
→ 인벤토리 확인 → 김치찌개 상세 레시피 생성 → 자동 저장

사용자: `/recipe 임박`
→ D-7 이내 재료 우선 추천 → 선택 후 저장

## 주의사항

- 인벤토리 JSON은 **읽기만** 함. 사용자가 명시적으로 요청하지 않는 한 수정하지 않음.
- "차감 결과"는 시뮬레이션이며 실제 파일 변경이 아님을 사용자에게 알릴 것.
- 알레르기/식이 제한 정보는 인벤토리에 없으므로, 사용자가 명시할 때만 고려.
- 저장 디렉토리(`week-4/레시피앱/recipe/`)는 이미 존재함. 없으면 `mkdir -p`로 먼저 생성.
- 마크다운 파일 저장은 `Write` 도구로만 (Bash heredoc / `cat > file` 금지).
